# v0.2.0-preview.17

## Fix: Codex remote plugin cache is now per account

Codex reconciles `plugins/cache/openai-curated-remote` against the ChatGPT account's own remote-install list every few minutes and deletes entries that list lacks. Earlier versions linked the whole `~/.codex/plugins` folder into every Codex profile, so accounts with different connected apps kept deleting and reinstalling each other's plugins. The changing skill list also made Codex re-insert its full instruction block into long threads, which inflated long-running sessions by tens of thousands of tokens per day.

- New Codex profiles get a real `plugins/` folder. `cache/openai-curated-remote` and `.remote-plugin-install-staging` are per profile; local marketplaces, bundled plugins and the plugin app server stay linked to the default home, so skills and local plugins remain shared.
- `linkCodexPlugins` is idempotent and can top up a profile after a new local marketplace is installed in the default home. Existing whole-folder links are left untouched.
- Regression test: `test/codex-plugin-isolation.js`.

Profiles created by earlier versions keep their whole-folder `plugins` link and are not rewritten automatically. To migrate one, replace the `plugins` link in that profile folder with a real folder whose shared entries link to `~/.codex/plugins` and whose two per-profile paths above are real folders (seed the remote cache with a copy of the shared one). Recreating the profile has the same effect.

## Features since preview.15

- API key profiles: register a key per Claude or Codex profile from the CLI (`apikey set|rm|status`, `add --with-api-key`) or the account panel. Claude keys are stored 0600 and injected only for that profile; Codex keys go through the official `codex login --with-api-key` for that `CODEX_HOME`. Keys are never accepted on argv or printed.
- Manual Codex reset-credit use from the panel, sharing the auto-use lock, idempotency key and log.
- Shared Antigravity (`agy`) login: save, check, switch and remove the shared OS login from the panel or `cli-accounts antigravity`, with backup and exact rollback. Per-account launch and managed delegation remain unsupported for Antigravity.
- EXAONE API category: per-account API keys for the LG AI Research EXAONE platform, `exaone run` with `EXAONE_*`/`OPENAI_*` injection for OpenAI-compatible tools, and a live `GET /v1/models` check. EXAONE is not a pinned CLI tool and is not a delegation target.

## Scope and compatibility

- Existing accounts, authentication, active selection, task results and data directories are preserved. No Gateway reconfiguration is required.
- Codex `skills`, `config.toml` and local plugin marketplaces are still shared with the default home; only the remote plugin cache and its install staging folder are isolated.
- Windows installers support the account app; managed task execution on Windows remains unsupported.
- These preview installers are unsigned. The release includes SHA256SUMS.txt for the published asset names.

## Personal edition

- Uses `.cli-accounts` and retains personal usage/credential metadata integrations.
- The shared account-tasks skill is maintained separately; installed skill snapshots in existing tasks are not silently rewritten by an app update.
