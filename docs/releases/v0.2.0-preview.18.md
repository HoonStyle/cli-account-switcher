# v0.2.0-preview.18

## New: Gemini API account category

Google ended Gemini CLI service for individual and Google AI Pro/Ultra accounts on 2026-06-18 and moved them to Antigravity CLI, which the Antigravity section already covers. Gemini therefore joins as an API-key category beside EXAONE: per-account Google AI Studio keys for OpenAI-compatible tools and Google's stateless `gemini-api` CLI.

- Panel section **Gemini API** and console commands `cli-accounts gemini-api …` (alias `gemini`): `list`, `add [--with-api-key]`, `apikey set|rm`, `use`, `rename`, `check`, `env`, `run [name] -- <command>`, `rm`.
- `run` strips inherited `GEMINI_*`, `GOOGLE_API_KEY`, `GOOGLE_GENAI_*` and `OPENAI_*` variables and injects the selected account's key as `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `OPENAI_API_KEY`, with `GEMINI_BASE_URL`/`OPENAI_BASE_URL` set to the Gemini OpenAI-compatible endpoint. No default model variable is injected.
- `check` calls `GET /v1beta/models` with the account key and records the available `gemini*` model names; error text is fixed wording and response bodies are never stored.
- Keys live in 0600 files under the data directory, are never accepted on argv, never printed, and never written to `state.json`. Gemini accounts are listed in `list --json` with `delegable: false`; they are not pinned, shimmed, or delegated.
- EXAONE and Gemini now share one provider implementation (`api-provider.js`, `provider-cli.js`); EXAONE behaviour, commands and messages are unchanged.

## Scope and compatibility

- Existing accounts, authentication, active selection, task results and data directories are preserved. A new empty `gemini-api` section is added to `state.json` on first load.
- The disabled Gemini CLI (OAuth) tool support is unchanged and remains off.
- Windows installers support the account app; managed task execution on Windows remains unsupported.
- These preview installers are unsigned. The release includes SHA256SUMS.txt for the published asset names.

## Personal edition

- Uses `.cli-accounts` and retains personal usage/credential metadata integrations.
- The shared account-tasks skill is maintained separately; installed skill snapshots in existing tasks are not silently rewritten by an app update.
