# 만료 전 리셋권 자동 사용

Codex 계정의 더 보기 메뉴 → **만료 10분 전 리셋권 자동 사용**. 계정마다 기본값은 꺼짐입니다. 설정을 켤 때 공식 Codex app-server로 현재 ChatGPT 계정을 확인합니다. 사용량 API 자동 조회 옵션과 독립적으로 동작하며, 활성 계정은 바꾸지 않습니다.

- 트레이 앱이 실행 중이어야 합니다. 패널을 닫아도 작동하고, 앱 종료·기기 절전 중에는 작동하지 않습니다.
- 만료 10분 전부터 30초 주기의 검사에서 처리합니다. 시작/절전 해제 시 즉시 확인합니다. 이미 만료된 리셋권은 새로 사용하지 않습니다.
- `status=available`, `resetType=codexRateLimits`, 개별 `id`와 유효한 `expiresAt`가 모두 확인된 리셋권만 대상으로 합니다. 개수만 알려진 경우 추측해서 사용하지 않습니다.
- 같은 리셋권 ID에는 모든 기기에서 동일한 결정적 UUID 중복 방지 키를 사용합니다. 계정명·설치 경로는 키에 포함하지 않습니다. 항상 `creditId`를 지정하며 다른 리셋권으로 자동 대체하지 않습니다.
- 한 기기에서 중복 실행은 `proper-lockfile`로 직렬화합니다. 서버의 `reset` / `alreadyRedeemed` 결과를 구분합니다. 개별 ID 지정 및 서버의 idempotency 계약에 의존하며, 실계정 동시 차감 테스트는 하지 않습니다.
- 같은 계정·리셋권의 자동 사용 요청은 이 기기에서 **최초 요청 포함 최대 3회, 요청 시작 기준 최소 1분 간격**입니다. 30초 검사 주기나 절전·네트워크 지연 때문에 실제 간격은 더 길 수 있습니다. 성공하면 즉시 추가 사용 요청을 멈춥니다.
- 초기화할 한도가 없으면 `nothingToReset`으로 기록하고, 남은 횟수 안에서 만료 전까지 같은 논리적 요청을 다시 확인합니다. 실제 사용 가능 여부는 서버가 결정합니다.
- 실패 응답을 받았다고 새 리셋권을 선택하지 않습니다. 응답을 잃은 요청은 저장된 특정 ID와 동일 키로 재확인합니다. 만료 후에도 **기존 요청 결과 재확인**은 가능하지만 같은 3회 제한에 포함됩니다. 3회 모두 응답을 잃었으면 결과 미확인 상태를 유지하고 추가 사용 요청을 멈춥니다.
- 횟수·다음 요청 가능 시각은 요청 전에 저장하므로 재시작·절전 복귀·옵션 재활성화로 초기화되지 않습니다. 업데이트 전 기록은 기존 로그에서 복원합니다. 서버로 보내기 전 중단된 예약도 보수적으로 한 번으로 계산합니다. 성공 후 한도 조회는 사용 요청 횟수와 별개로 계속 확인할 수 있습니다.
- 재로그인 또는 확인된 ChatGPT 계정 변경 시 옵션을 끕니다. 켜진 상태에서 다른 프로필로 전환해도 해당 계정의 예약은 유지됩니다.

## 로그와 확인 의미

계정별 설정 폴더의 `reset-auto-use.jsonl`. 메뉴의 **리셋권 자동 사용 로그 파일 보기**에서 파일 위치를 엽니다. 시각은 UTC ISO 8601로 기록하고 화면에서는 OS 현지 시각으로 표시합니다.

| 필드 | 의미 |
| --- | --- |
| `attemptedAt`, `requestedAt` | 논리적 시도 시작 시각, 이번 요청 시각 |
| `attemptCount` | 해당 계정·리셋권의 누적 요청 예약 횟수(최초 포함) |
| `event=stopped`, `reason=attemptLimit`, `stoppedAt` | 3회 제한으로 추가 요청을 중단한 시각. 기존 기록이 3회를 넘으면 원래 횟수를 보존 |
| `usedAt` | 이 요청이 `reset` 응답을 받은 로컬 시각. 서버가 제공한 원래 사용 시각은 아님 |
| `acknowledgedAt` / `respondedAt` | 응답을 확인한 시각 |
| `apiOutcome` | `reset`, `alreadyRedeemed`, `nothingToReset`, `noCredit`, 또는 결과 미확인 `unknown` |
| `serverResetAcknowledged` | 서버가 사용 완료/이미 사용 완료를 응답했는지 |
| `verifiedAt` | 사용 후 한도를 재조회한 시각 |
| `before`, `after` | 1차/2차 한도의 사용률과 자동 초기화 예정 시각 |
| `resetConfirmed` | 재조회에서 사용률 감소를 관찰하면 true, 비교 가능하지만 감소하지 않았으면 false, 재조회/비교 불가면 null |

`resetConfirmed=false`는 서버의 사용 실패와 같지 않습니다. 동시 사용이나 다른 기기의 먼저 처리된 요청 때문에 감소를 관찰하지 못할 수도 있습니다. 서버 응답과 관찰 결과를 별도로 보존합니다. `alreadyRedeemed`에는 실제 최초 사용 시각이 제공되지 않으므로 `usedAt=null`로 기록합니다.

로그에는 토큰·이메일·원본 리셋권 ID를 남기지 않습니다. 중복 재시도를 위한 원본 ID는 별도 비공개 `reset-auto-use-state.json`에만 보관하며, 상태/로그 파일은 소유자 읽기·쓰기 권한으로 생성합니다.

## 검증

- `npm run test:reset-auto`: 가상 계정 회귀 시나리오와 Chromium UI 조작/레이아웃 검증.
- `npm run test:reset-integration`: 별도 HOME/PATH/설정과 가짜 공식 CLI 서버를 이용한 실제 main/preload/UI 통합 경로. `.asar` 경로를 테스트 스크립트에 넘기면 패키지 그대로 검증합니다.
- 일반 회귀: `npm test`, `node test/delegation.js`.
- 공식 CLI 0.160.1의 생성 스키마에서 `account/rateLimitResetCredit/consume`의 `creditId`, `idempotencyKey`, 응답 enum을 확인했습니다.
- 실제 리셋권을 소모하는 테스트는 하지 않습니다. 설치/실행 적용과 옵션 활성화는 별도 단계입니다.

### 1분 간격·3회 제한 후속 검증

- 자동 사용 회귀 20개 통과. 59,999ms에는 요청하지 않고 60,000ms부터 다음 요청 가능, 최초 포함 3회 후 중단.
- 강제 확인·앱 재시작·옵션 off/on·동시 프로세스에서도 횟수/간격 유지. 기존 11회 로그를 가진 리셋권에 새 요청 예산을 주지 않음.
- 응답 유실/만료 후 재확인도 같은 제한 적용. 3번째 요청 성공 후 한도 조회 실패는 소비 없이 재조회 가능. 실제 계정/리셋권은 테스트에서 사용하지 않음.

공식 프로토콜: https://learn.chatgpt.com/docs/app-server#8-earned-rate-limit-resets-chatgpt
